## 1. АРХИТЕКТУРА

### 1.1 Persons-центричность

```
cfr_persons (все люди — клиенты, тренеры, админы)
    ├── cfr_clients (1:1 → persons)      ← клиенты студии
    ├── cfr_teachers (1:1 → persons)     ← преподаватели
    └── cfr_admins (1:1 → persons)       ← администраторы CRM
```

В `cfr_persons`: ФИО, пол, дата рождения, телефоны, email, parent_person_id_1/2 (ссылки на persons), адрес, заметки.
Без пароля, без роли — только личные данные.

### 1.2 Единая таблица сущностей

```
cfr_entities (группы, индивид. тренировки, аренда, массаж, сплит)
    ├── cfr_group_clients (M:N → persons)     ← состав групп
    ├── cfr_schedule_entries (1:N)            ← расписание
    ├── cfr_accounts (1:N)                    ← абонементы
    ├── cfr_visits (1:N)                      ← визиты
    └── cfr_reservations (1:N)                ← бронирования
```

### 1.3 Интеграция с сайтом

| Сущность сайта | Действие |
|---|---|
| `users` | Остаётся. `cfr_persons.site_user_id` → `users.id` |
| `trainers` | → `cfr_teachers` (данные мигрируют) |
| `trainer_photos` | → `cfr_media` (entity_type='teacher') |
| `user_subscriptions` | → `cfr_accounts` |
| `user_visits` | → `cfr_visits` |
| `user_payments` | → `cfr_transactions` |
| `programs` | Объединяется с `cfr_styles` |
| `pages.json` | → `cfr_pages` |
| `footer.json` | → `cfr_footer` + `cfr_footer_links` |
