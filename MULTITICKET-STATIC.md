## 📂 КОРЕНЬ И СТЕК

- **Корень сайта:** `/home/ivan/Рабочий стол/проекты/цфр/cfr-site/static/`
- **Данные:** `db.json` в корне репо
- **Генератор статики:** `scripts/export-static.mjs` → `npm run static:export` → `static/js/data/*.js`
- **Данные Яндекс.Диска:** `static/data/` (не коммитить — гигабайты)
- **Загрузка файлов:** `static/uploads/` (копия `uploads/` в корне для Next.js)
- **Стек статики:** чистый HTML + ES5/ES6 JS + один `css/style.css`. Сборки нет.
- **Локальный просмотр:** `cd static && python3 -m http.server 8080`

### Пайплайн данных

```
Яндекс.Диск (docx/фото) → скрипты в scripts/ → db.json → export-static.mjs → static/js/data/*.js → статика
```

## 🔑 КЛЮЧЕВЫЕ РЕШЕНИЯ (приняты, не переигрывать)

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | **Разделы программ = папки Яндекс.Диска** (`БОЕВЫЕ/ДЕТСКИЕ/ОБУЧАЮЩИЕ/ОЗДОРОВИТЕЛЬНЫЕ/ФУНКЦИОНАЛЬНЫЕ`). Хранится в `programs[].category` | Пользователь: «разделы программ — папка, в которой они сгруппированы» |
| 2 | Каждый раздел на странице программ — **сворачиваемая панель** (`<details>` или класс `.collapsible`) | Требование пользователя |
| 3 | Скрытие из выдачи — флаг `hidden: true` у программы/тренера. **Сейчас скрыты:** программа «Греко-римская борьба», тренер «Поторочин Станислав» | Требование пользователя |
| 4 | Скрытые объекты **не попадают** ни в `navPrograms/navTrainers`, ни в `programs.js/trainers.js`, ни в генерацию страниц | Иначе «скрыть» ничего не делает |
| 5 | Плитки на главной и на общих страницах — **только фото, заголовок, кнопки**. Текст — по клику (модалка или страница) | Требование пользователя |
| 6 | Расписание и цены — **картинками** (не таблицами). Все картинки кликабельны → **lightbox** | Требование пользователя |
| 7 | Ссылка на **BALLOO убрана** из футера | Требование пользователя |
| 8 | Текст новостей хранится в **markdown**. Ограничение 9999 символов считается **по видимому тексту без разметки** | Требование пользователя |
| 9 | Первые **200 символов** = короткий текст для предпросмотра. Если длиннее — новость разворачивается **в отдельном окне** (модалка) | Требование пользователя |
| 10 | **Админке нужен сервер** — в голой статике пароль и сохранение новостей невозможны. Решение: `scripts/admin-server.mjs` (Node, localhost) принимает изменения, пишет `db.json`, перегенерирует статику | Иначе «реальная функциональность раздела Новости» невыполнима |
| 11 | Пароль **не хардкодить** в коде и репо (правило AGENTS.md). Читать `process.env.ADMIN_PASSWORD`; значение `ЦФР_2026.10.21` лежит в `.env.local` (в `.gitignore`) | Правило №2 AGENTS.md |
| 12 | Фото, **не привязанные** к тренеру/программе, — на страницу **«Альбом»** | Требование пользователя |
| 13 | Фото с диска **не коммитятся как есть**: качаем в `static/data/`, оптимизируем (jpg/webp, ≤1600px, превью ≤400px) в `static/uploads/`, в `db.json` — только путь в `uploads/` | Исходники по 10–15 МБ, сайт не должен весить гигабайты |
| 14 | `Turbopack` запрещён, `next build --webpack` — не трогать. Статика к Next.js не относится и сборки не требует | Правило №1 AGENTS.md |
| 15 | **Один шаблон на тип сущности**, а не файл на каждую: `program.html?id=N`, `trainer.html?id=N`, `news.html?id=N`. Данные рендерит `js/entity.js` из уже существующих `js/data/*.js` | Отдельные HTML на 30 программ = дублирование и рассинхрон. Шаблон один — правка в одном месте |
| 16 | Скрытый/несуществующий `id` в шаблоне → блок «Не найдено» + ссылка на общий список, а не 404 | Головая статика не отдаёт коды ответа |
| 17 | Markdown рендерит `static/js/md.js` — один парсер на сущности и новости. `MD.plainText()` снимает разметку (для лимита 9999 и предпросмотра), `MD.preview(text, 200)` — короткий текст | Требование: теги разметки в лимит не входят |

> сервер возвращает токен в теле login и принимает `Authorization: Bearer` (+cookie), CORS разрешает Authorization;
> клиент хранит токен в localStorage, шлёт Bearer во всех запросах (включая upload).
> **Использование:** `npm run admin` → открыть http://localhost:3456/admin.html (пароль в `.env.local`).
> Вход с любой страницы сайта тоже работает, пока админ-сервер запущен.

**Причина:** `admin.html` открывают со статического сервера (8080/NGINX), а API живёт на `admin-server.mjs` (3456).
Относительный `fetch('/api/admin/login')` уходит на статический сервер, где API нет → 405/404.

**Фикс:**
1. `admin.html`: `API_BASE` = тот же origin, если порт 3456, иначе `http://<hostname>:3456`; все fetch через него.
2. `admin-server.mjs`: токен возвращается в теле login-ответа; принимается из заголовка `Authorization: Bearer`
   (cookie остаётся); CORS разрешает Authorization.
3. `admin.html`: токен в localStorage, заголовок Authorization во всех запросах (заголовок Cookie браузерами игнорируется).

**Критерий готовности:** вход работает при открытии admin.html и с :3456, и с другого порта (при запущенном админ-сервере).

**Фикс:**
1. `entity.js`: убрать ложную обёртку с классом `week-board` — оборачивать только в `<div class="trainer-week-board">` (без grid-классов)
2. CSS `.trainer-week-board`: full-bleed на всю ширину окна —
   `width: 100vw; margin-left: calc(50% - 50vw)` (контейнер `.entity-page` — 900px, доска 1050px+ требует всей ширины)
3. Защита от горизонтального скролла из-за `100vw` (100vw включает вертикальный скроллбар):
   `body[data-entity="trainer"] { overflow-x: clip; }` — `clip` не ломает sticky-шапку (в отличие от `hidden`)
4. Внутренний отступ доски: `.trainer-week-board .week-board-wrap { padding: 0 0.75rem 0.5rem }` — чипы не липнут к краю экрана

**Критерий готовности:**
- «Мои тренировки» = корректная недельная доска (7 колонок Пн–Вс) на полную ширину страницы
- Никакой вложенной сетки, доска не сжата

### S62 — Фотоальбом программы/тренера: карусель из необрезанных фото

**Цель:** на страницах программы и тренера блок «Фотоальбом» — **горизонтальная карусель**, в которой каждое фото показано **целиком** (без crop/обрезки).

   - Счётчик `.carousel-counter` в формате `3 / 8` — обновляется при прокрутке
   - `img`: `max-height: 420px; width: auto; object-fit: contain` — **без обрезки**, натуральный aspect ratio
   - Клик по фото → `window.openLightbox(src, alt)` (lightbox уже показывает фото целиком)
   - Свайп работает «из коробки» через нативный скролл + scroll-snap
   - Деградация без JS: если модуль не загружен — сетка `.album-grid` (старое поведение)
2. **`entity.js`**: `albumHtml()` вызывает `window.Carousel.render(...)`, обёртка `.entity-album`; `<h2>Фотоальбом</h2>` остаётся
3. **CSS**: блок `.entity-carousel`/`.carousel-*` в `style.css`; скрытие кнопок, когда фото одно; `scrollbar-width: none` + `::-webkit-scrollbar { display: none }` (стрелки вместо полосы); мобильный `max-height: 280px`
4. **Не трогать `album.html`** — там остаётся сетка `.album-grid-page` (это отдельная страница-сетка, не фотоальбом сущности)
5. **`program.html` и `trainer.html`** — подключить `js/carousel.js`
6. **Тесты `test-static.mjs`**: на странице сущности с `photoAlbum` есть `.entity-carousel`, `.carousel-track`, `img` с `object-fit: contain` в CSS, **нет** `.album-grid` внутри блока «Фотоальбом», карусель подключена на обеих страницах

**Критерий готовности:**
- «Фотоальбом» — горизонтальная карусель, фото целиком (не обрезаны)
