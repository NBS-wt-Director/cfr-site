## 2. ОБЩАЯ СТРУКТУРА

### 2.1 Шапка и подвал
- **SiteHeader** — общая, как на всех страницах сайта (fixed, 64px на десктопе, 56px на мобильном)
- **Footer** — общий, как на всех страницах (контакты, навигация, соцсети)

### 2.2 Навигация
- **Desktop (≥ 1024px):** sidebar слева (280px), всегда виден
- **Tablet (768–1023px):** sidebar слева (240px), всегда виден
- **Mobile (< 768px):** bottom navigation (4 пункта), всегда видна. Сайдбар отсутствует.

### 2.3 Доступность (WCAG)
- Базовый размер текста: **18px**
- Минимальная высота кнопок: **48px**
- Поля ввода: **18px** шрифт, **50px** высота
- Фильтры: **50px** высота

### 2.4 Подвкладки (для родителей)
- **Показываем ТОЛЬКО если есть семья:**
  - «Я» — всегда (cfr_persons текущего пользователя)
  - «Дети» — если есть дети (cfr_persons.parent_person_id → children)
- **Сородитель НЕ показывается**
- Если семьи НЕТ — подвкладки НЕ показываем
- Внешний вид: ТОЛЬКО имена (без фото/аватаров)
- Горизонтальный скролл, кнопки листания ← →

## 3. РАЗДЕЛЫ

### 3.1 📊 Обзор (дашборд)
**Блоки (по порядку):**
1. Баннер именинника (если ДР в ближайшие 3 дня) — БЕЗ кнопки «Записаться»
2. Подвкладки (Я / Дети) — горизонтальный скролл
3. Ближайшая тренировка (дата, время, группа, тренер, зал)
4. Статистика (кликабельные карточки):
   - **Остаток:** `~ N тренировок` + суммарно за 31 день в рублях
   - **За 31 день:** количество посещений
   - **Бонусы:** акционные бонусы по акции «Приведи друга»
   - **Оплачено / потрачено:** обе цифры сразу (`3 140 ₽ / 2 400 ₽`)
5. Последние 5 визитов (только за последние 31 день)
6. Кнопка «Посмотреть все посещения»

### 3.2 📅 Посещения
**Поля таблицы:**
| Колонка | Описание |
|---------|----------|
| Дата | Дата + время визита |
| Программа | Название группы/тренировки |
| Тренер | **Только имя** (без фамилии/отчества) |
| Зал | Название зала |
| Тип | Групповая / Персональная |
| Стоимость | Стоимость визита — **всегда указана** |

**Фильтры:** по месяцу, по программе
**Пагинация:** 20 записей на страницу
**Мобильная версия:** строки кликабельные — раскрывается карточка с деталями

### 3.3 💰 Оплаты и списания

**Поля таблицы:**
| Колонка | Описание |
|---------|----------|
| Дата | Дата операции |
| Тип | Оплата / Пополнение / Списание (с подтипом) |
| Сумма | Сумма (зелёный / красный / серый) |
| Описание | Назначение |
| Статус | Завершён |

**Типы списаний (ОБЯЗАТЕЛЬНО разделять):**

| Тип списания | Описание | Пример описания | Цвет |
|-------------|----------|-----------------|------|
| `Тренировка` | По конкретному посещению | «Кунг-фу · 04.08.2026» | Красный `-X ₽` |
| `Возврат` | Возврат средств | «Возврат за пропуск» | Зелёный `+X ₽` (с пометкой «Возврат») |
| `Окончание срока` | Истёк срок абонемента | «Абонемент „Кунг-фу" 12 занятий — истёк» | Серый/оранжевый `—` |

**Цветовая индикация:**
- **Оплата / Пополнение** → зелёный `+X ₽`
- **Списание (тренировка)** → красный `-X ₽`
- **Возврат** → зелёный `+X ₽` (с пометкой «Возврат»)
- **Окончание срока** → серый/оранжевый (информационное)

**Итого:** Всего оплачено, всего потрачено (31 день), баланс депозита
**Мобильная версия:** строки кликабельные — раскрывается карточка с деталями (дата, тип, подтип, сумма, описание, статус)

### 3.4 📜 Сертификаты ⚠️ В РАЗРАБОТКЕ

- Логика сложнее, нужна интеграция с CRM

### 3.5 🎫 Абонементы ⚠️ В РАЗРАБОТКЕ

### 3.7 📓 Дневник самоконтроля ⚠️ В РАЗРАБОТКЕ

## 9. ИТОГОВЫЙ ПУТЬ ПОЛЬЗОВАТЕЛЯ

```
1. Открывает /lk
2. Видит шапку сайта + форму входа + подвал сайта
3. Вводит телефон + договор → нажимает «Войти»
4. Попадает на дашборд (обзор)
   ├── Шапка сайта (всегда видна)
   ├── Меню (всегда видно: слева на десктопе, снизу на мобильном)
   ├── Подвал сайта (внизу)
   ├── Если ДР: баннер-поздравление (без кнопки)
   └── Если родитель: подвкладки (Я / Дети)
5. Переключается между вкладками через меню
6. Заглушки показывают что будет (без сроков)
7. Выход через кнопку в меню
```

## 10. ПОМЕТА ДЛЯ БЭКЕНДА — рендеринг имён

> У большинства записей ФИО хранится целиком в поле «Фамилия» ИЛИ в поле «Имя».
> При рендеринге во вкладках людей учитывать эту логику:
> - Если в поле «Имя» пусто → брать из «Фамилии» (и наоборот)
> - В макетах: «Я», «Миша», «Катя» — это заглушки
> - На продакшене: рендерить то, что есть в БД, не терять данные
