# S141 — Единая обработка ошибок «не найдено»: 404.html с журналом и письмом

> Закрыт: 2026-11-07, выполнено — 404.html в каркасе сайта, случайные ссылки, log-404 API, JSONL-журнал, email с анти-спамом, redirect из entity/directions/page/news, 500.html обновлён.

> **Статус:** 🔴 Активен (волна 5, седьмой в очереди)

> **Порядок волны 5:** S137 → S138 → S139 → S134 → S135 → S140 → **S141** → S142 → S101 (деплой)
> ⚠️ Решение 16 («не отдавать 404») **отменено пользователем** с 2026-11-07.

## Постановка (дословно от пользователя)

«все ошибки вида "... не найдено" обработываются единым 404.html который:
— содержит шапку, уведомление об ошибке (КРАСИВОЕ) со ссылкой на главную и случайными ссылками;
— записывает в журнал ошибку. даже откуда пришёл пользователь и информацию об устройстве;
— отправляет на техническую почту письмо об ошибке».

## Факты

1. `static/404.html` существует, но **изолирован** от сайта: без шапки/подвала/меню,
   чужие цвета (`#2563eb`), без ссылок на разделы.
2. Страницы сущностей при скрытом/несуществующем `id` показывают встроенный блок
   `.entity-not-found` (решение 16) — пользователю теперь нужна **единая** страница.
3. NGINX: `error_page 404 → /404.html` уже настроен (этап A).
4. Почта: `nodemailer` + `db.emailConfig` уже работают (письма заявок, `admin-server.mjs:998+`).

## Шаги

1. **Переделать `404.html`:** каркас сайта (header.js/footer.js/core.js/appearance.js, `?v=`),
   крупное аккуратное уведомление («Страница не найдена», 404), кнопка/ссылка «← На главную»,
   блок «Возможно, вы искали» — 3–5 **случайных** рабочих ссылок (разделы сайта + случайные
   программы/тренеры/новости из `SITE_DATA`, без повторов). Тот же вид — у `500.html` (минимум —
   тот же каркас).
2. **Единый вход для клиентских «не найдено»:** `entity.js`, `page.js`, `news.html?id=`,
   `directions.html?id=` при отсутствующей/скрытой записи — редирект на
   `404.html?from=<страница>&id=<id>` (или инлайновый рендер того же блока — выбрать одно;
   редирект предпочтительнее ради журнала). Решение 16 («не 404») **отменяется пользователем**
   с 2026-11-07; для поисковиков deep-link остаётся валидным URL (canonical), робот на 404
   не натыкается (в sitemap скрытые/id-несуществующие не попадают).
3. **Журнал ошибок:** на показе 404 клиент шлёт `POST /api/admin/log-404` (эндпоинт **без
   авторизации**, только запись): `{ url, from (document.referrer), ua, screen, ts }` →
   сервер дописывает строку в `logs/404.log` (JSONL). Ошибка логирования не должна ломать
   страницу (fetch с `catch`).
4. **Письмо на техническую почту:** при записи в журнал — письмо через существующий
   `nodemailer`/`emailConfig` (кому: `emailConfig.techEmail`, дефолт — `smtpUser`; тема
   «404 на центр-фр.рф: <url>», тело: url, referrer, UA, дата, экран). **Анти-спам:**
   не чаще одного письма в 5 минут на один `url` (кэш в памяти сервера); журнал пишет **все**
   случаи, письмо — агрегированно.
5. Тесты: `test-static` — 404.html содержит header-container/ссылку на главную/блок случайных
   ссылок; `node --check`; смоук: `POST /api/admin/log-404` без токена → 200 + строка в логе;
   повтор в течение 5 мин → письмо не дублируется.

## Критерий готовности

Любая «не найдено» (NGINX-404, скрытая сущность, битый `?id=`, удалённая
страница) показывает один и тот же красивый 404 в каркасе сайта; случайные ссылки ведут
на живые страницы; каждая ошибка в `logs/404.log` с referrer и UA; техпочта получает письма
без лавины дублей.
