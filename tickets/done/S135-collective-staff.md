# S135 — «Коллектив»: персонал и администраторы наравне с тренерами

> Закрыт: 2026-11-07, выполнено — раздел «👥 Персонал» в админке, экспорт staff.js, панель «Администраторы» на trainers.html (скрыта если нет видимых), API get/save-staff, help-секция.

> **Статус:** 🕐 Отложен → РАЗМОРОЖЕН (сессия 35), в очереди волны 5 после S134


## Постановка (дословно, 2026-11-05)

«Коллектив (так как в будущем туда будут добавлены и Администраторы)» (Р1).

## Уточнение пользователя (2026-11-07, разморозка)

«коллектив с администраторами разморозь, но **в админке добавь раздел** и **если админов нет или они все скрыты — не показывай подраздел**».
То есть: ① в админке — **отдельный раздел** управления персоналом (не внутри тренеров);
② на публичной странице подраздел/панель «Администраторы» выводится **только при наличии хотя бы одной видимой (не `hidden`) записи `staff`** — пустой список не показывает ни пустой панели, ни заголовка.

## Факты (проверено 2026-11-05)

В `db.json` на верхнем уровне есть `staff` — 1 запись
`{ id: "1", name: "Анна Смирнова", image: <внешний URL unsplash>, role: "Администратор" }`
и пустой массив `employees`. Ни `staff`, ни `employees` **не экспортируются** на статический
сайт (`export-static.mjs:152` использует строку `'staff'` только как **ключ пункта меню**,
а не как данные). У тренеров есть `isDirector` (1 запись) — публично не показывается (правило
волны 3, T9.1), для публичного статуса предусмотрено новое поле `publicTitle`.

## Суть

Раздел «Коллектив» должен уметь показывать людей **не только с сущностью `trainer`**:

1. Модель вывода: единый «участник коллектива» = `{ kind: 'trainer' | 'staff', name, image, publicTitle, role/category, link }`; `Tiles.trainer` дополнить общим вызовом `Tiles.person` (или параметром `kind`), разметку сетки/панелей не дублировать.
2. Экспорт: `staff` → `static/js/data/staff.js` (или срез в `trainers.js`) **с фильтром** `visible`/`hidden` и без полей CRM; `image` — только локальный путь `uploads/…` (внешний unsplash-URL в базе заменить загрузкой файла, иначе на проде картинка бьётся).
3. **Админка — отдельный раздел** «👥 Персонал» (не внутри «Тренеры»), группа «Данные»: CRUD `staff` (ФИО, роль, фото с загрузкой, 👁🙈, порядок drag-and-drop) — по образцу S100/S113; API `get/save-staff` + санитизация (id, имя ≤120, роль ≤60, `image` — только локальный `uploads/…`, `hidden`); запись в `db.staff` с бэкапом и `regenerateStatic()`. Публичный статус тренера — через новое поле `publicTitle` (например «Директор центра»), **не** через `isDirector`.
4. `trainers.html`: панели «Тренеры» / «Администраторы» (роль = `staff.role`), группировка — тем же компонентом `.collapsible` из S128 шаг 4; страница не-тренера при отсутствии `trainer.html` для него — модалка или `page.html` (решить с пользователем). **Панель «Администраторы» не выводится вообще** (ни заголовка, ни пустой сетки), если видимых записей `staff` ноль — проверка по экспортированному (уже отфильтрованному) списку, а не по сырой базе. Тренерская часть страницы от этого не меняется.
5. JSON-LD (`seo.js`): `Person` + `employee` внутри `Organization` для staff-записей.
6. Тесты: round-trip CRUD staff, вывод панели «Администраторы» при непустом видимом списке, **отсутствие панели (и её заголовка) при пустом/полностью скрытом списке**, отсутствие внешних URL в экспортируемых картинках, `publicTitle` в плитке/странице, `isDirector` по-прежнему не попадает в публичный экспорт, наличие раздела «👥 Персонал» в админке.

## Критерий готовности

В разделе «Коллектив» администратор появляется из админки без правки кода; тренеры и не-тренеры используют одну сетку/панели/плитку; ничего из полей `trainers`/`staff` не потеряно; **при отсутствии видимых администраторов подраздел «Администраторы» на сайте не показывается**.
