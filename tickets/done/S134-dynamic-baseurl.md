## Постановка (дословно, 2026-11-05)

«да, но в будущем сделай динамической» — про хост для `baseUrl` (Р3).

## Суть

Сейчас хост для `canonical`/`og:url`/`sitemap.xml`/`robots.txt` — значение по
умолчанию `https://центр-фр.рф` (в S133 п.7 поле в «🏠 Главные данные» уже закладывается).
Задача — сделать его полностью управляемым и безопасным при смене:

1. `siteSettings.baseUrl` — единственный источник хоста для **всех** SEO-ссылок; в коде
   (`scripts/lib/sitemap.mjs`, `static/js/seo.js`) не должно остаться литерала домена.
2. Санитизация: `https://`, без завершающего `/`, без пути/query/пробелов; IDN разрешён
   (хранится как ввёл админ).
3. Смена хоста ⇒ автоматическая перегенерация `sitemap.xml`/`robots.txt` (вызов того же
   модуля, что кнопка `regenerate-seo`) + toast с числом URL.
4. `og:url`/`canonical` на фронте читают `SITE_DATA.siteSettings.baseUrl` (уже экспортируется),
   при пустом значении — fallback на `location.origin`, чтобы локальный прогон
   `python3 -m http.server 8080` не писал canonical на прод.
5. Проверка обоих написаний домена на проде (`центр-фр.рф` и `xn----itbymbjqk.xn--p1ai`) —
   `curl -I https://…/sitemap.xml`, Content-Type `application/xml`; вывод зафиксировать в
   `DEPLOY.md`.
6. Тесты: смена baseUrl в базе → `<loc>` и `Sitemap:` меняются, IDN→punycode, двойной запуск
   идемпотентен, пустой baseUrl → fallback на `location.origin` в `seo.js`.

## Критерий готовности

Хост сайта меняется из админки без правки кода; все SEO-ссылки (canonical/og/sitemap/robots)
обновляются автоматически; локальный прогон не пишет canonical на прод.
