# SEC-DB: тикеты безопасности/схемы БД направлены в архивированную Next.js-версию

> Создан: 2026-11-07 (сессия уборки). Статус: 🕐 **ОЖИДАЕТ РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ.**

## Суть проблемы

При разделении мультитикетов `TICKET-SECURITY-FIXES.md` и `TICKET-DB-001/DBSCHEMA`
(перенесены в `tickets/trash/`) были созданы 11 отдельных тикетов:

- `SEC-01…SEC-10` (авторизация админ-маршрутов, лимит загрузки, rate limiting,
  git cleanup db.json, package-lock, CORS, Content-Type, yandex-disk токен,
  next.config.js, favicon)
- `DB-001` (16 CRM-таблиц в `docker/init-crm.sql`)

**Факт проверки (2026-11-07):** все они описывают **Next.js-код**, которого в рабочем
дереве **нет**:

| Путь из тикетов | Реальность |
|-----------------|-----------|
| `src/app/api/**`, `src/lib/auth.ts`, `src/middleware.ts` | ❌ каталога `src/` нет |
| `next.config.js` | ❌ файла нет |
| `docker/init.sql`, `docker-compose.yml` | ❌ каталога `docker/` нет |
| `public/favicon.ico` | ❌ каталога `public/` нет |

Старая Next.js-версия лежит в **`trash/`** (в `.gitignore`, не деплоится).
Рабочий стек: статика `static/` + `scripts/admin-server.mjs` (:3456).

## Что нужно решить пользователю

### ✅ П.1 РЕШЕНО (2026-11-07) — вариант (b)
Пользователь: **«next версия вернётся в 3х экземплярах — crm, api и web-морда собранная
на дизайне static. всё будет связываться с одной psql и подниматься на docker»**.
→ SEC-01…SEC-10 и DB-001 **остаются в `definded/`** до старта
[NEXT-001](NEXT-001-next-return-3-apps.md). Требования применять при написании
новых маршрутов API/CRM (этапы 4–5 плана), а не «латать» архивный код.

### П.2 Живые пункты для текущего стека (не зависят от NEXT-001)
- **Favicon** — решение пользователя 2026-11-07: берётся **из загруженного логотипа**
  (`settings.siteSettings.logo`), а не из фиксированного `logo.png`
  (см. [SEC-10](SEC-10-favicon.md));
- аудит `admin-server.mjs`: лимит размера uploads, CORS `*` (сузить до
  центр-фр.рф), проверка Content-Type на POST API.

### П.3
**DB-001** — выполнять на этапе 2 NEXT-001 (общая psql в Docker), файл `docker/init-crm.sql`.
