# S1–S3 — Фото: скачка с Яндекс.Диска → оптимизация → раскладка

> **Статус:** ⏸ Приостановлены по решению пользователя («давай фотографии потом»), 2026-10-21

> **Блокер:** возобновление — только по команде пользователя (фактически участие пользователя).

## S1 — Скачка всех фото с Яндекс.Диска

**Цель:** все изображения с обоих дисков лежат в `static/data/trainers/` и `static/data/programs/` с сохранением структуры папок.

**Текущее состояние:** Яндекс отдаёт `HTTP 500`/`read timeout` на файлах >10 МБ. Всего на дисках **1187 фото** (1115 тренеры + 72 программы). Скачано ~84 (на момент паузы; ночной сканер `night-sync.mjs` на сервере продолжает докачивать).

**Шаги:**
1. Запустить/перезапустить `scripts/yandex-download.py` до полного завершения (resume по `.download-progress.json`). Контроль: `tail -f static/data/.download.log`
2. Добавить в скрипт повтор при `HTTP 500` и таймаутах (не менее 3 попыток на файл) — сейчас файл просто теряется.
3. Построить инвентарь `static/data/.inventory.json`: путь, имя, размер, ширина×высота, MIME.
4. Сверить инвентарь с деревом диска — ни одна папка не должна остаться пустой.

**Критерий готовности:** количество скачанных фото = количество фото в дереве диска; `.inventory.json` создан; ошибок нет.

## S2 — Оптимизация фото для веба (зависит от S1)

**Цель:** из исходников 3–15 МБ сделать веб-версии.

**Шаги:**
1. Скрипт `scripts/optimize-media.mjs` (или `.py`): для каждого фото из `.inventory.json`
   - **полный размер** — максимум 1600px по длинной стороне, JPEG q=82 → `static/uploads/full/<slug>/<file>.jpg`
   - **превью** — максимум 400px → `static/uploads/thumb/<slug>/<file>.jpg`
2. Имена файлов — латиницей/без пробелов (кириллица в URL ломается).
3. Сгенерировать `static/data/.optimized.json`: `исходник → {full, thumb, w, h}`.
4. Проверить суммарный вес — цель **< 200 МБ**.

**Критерий готовности:** все фото имеют full+thumb; `static/uploads/` < 200 МБ; пути ASCII.

## S3 — Разложить фото по тренерам и программам, остаток — в Альбом (зависит от S1)

**Цель:** у каждого тренера и программы заполнены `image` (обложка) и `photoAlbum[]`; непривязанные фото идут в `album[]`.

**Шаги:**
1. Смэпить папки диска на записи `db.json`:
   - `programs/<РАЗДЕЛ>/<Программа>/` → `programs[]` по имени + `category` из `<РАЗДЕЛ>`
   - `trainers/<Имя Фамилия>/` → `trainers[]` по имени (учесть расхождения: `Гимнастика для шеи и органов чуств` (опечатка на диске) → `Гимнастика для шеи и органов чувств`; `ОФП УШУ (10+)` → `ОФП Ушу (10+)`; `Растяжка ` с пробелом на конце)
2. Обложку брать по правилам: файл с именем программы/тренера (`.jpg`/`.png`) → иначе первое по алфавиту. **Согласовать с пользователем (открытый вопрос 2).**
3. `photoAlbum: [{ image, caption }]` — все остальные фото этой папки.
4. Всё, что не смэпилось (папки «СОВМЕСТНЫЕ ФОТО», «Фото тренеров/С большим расширением», «Тренеры отдыхают», «хорошие тренера вместе» и т.п.) → новый массив `db.json` `album: [{ id, image, thumb, title, date }]`.
5. Скрипт записывает результат в `db.json`, печатает отчёт «смэплено / в альбом / потеряно».

**Критерий готовности:** у всех видимых (не `hidden`) тренеров и программ есть `image` и непустой `photoAlbum`; `album[]` заполнен; «потерянных» фото нет.
