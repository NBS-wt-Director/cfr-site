# S136 — Админка «Альбом»: общий альбом «Коллектив», CRUD альбомов, неиспользуемые фото

> **Статус:** 🕐 Отложен — выполнять **после волны 4 и S101 (деплоя)**, по прежней договорённости


## Постановка (дословно, 2026-11-06)

«в админка.альбом задай следующие объекты:
- "Общий альбом "Коллектив"" (отображается в слайдере на странице "коллектив", по умолчанию пуст)
- crud сущностей "альбомы" (отображаются как слайдеры на странице альбомы. у каждого — отдельный заголовок, у каждого кадра свой заголовок, если есть хотя бы один — отображаем страницу альбом)
- "не используемые фотографии".»

## Факты (проверено 2026-11-06 по коду и базе)

1. Сейчас в админке один объект: «📸 Альбом» (S114) — CRUD **плоского** списка `data.album[]` = `{ id, image, thumb, title, category, date }`. В базе **1001 запись**, категории: «Фото тренеров» 324, «Тренеры» 151, «Тренеры общая» 281, «Тренеры отдыхают» 122, «Программы» 89, «Совместные фото» 14, «Архив тренеров» 16, «Архив программ» 4.
2. Слайдер совместных фото на странице «Коллектив» берёт кадры **жёстко по строке категории**: `export-static.mjs:607` — `db.album.filter(a => a.category === 'Совместные фото')` → `trainer-slider.js` (T7.4). Управляемого «альбома для слайдера» нет. S128 шаг 5 уже требует вынести интервал/вкл-выкл/категорию-источник в настройку — в S136 источник заменяется на «Общий альбом "Коллектив"» (не конфликтует: S128 делает настройку, S136 даёт ей содержимое).
3. `album.html` — одна сетка с фильтрами по `category` (`#album-filters`), empty-state `#album-empty`; страница **выключена из навигации** (шапка/подвал) с S71, доступна напрямую. Модуль данных — `static/js/data/album.js` (258 КБ).
4. Ночной сканер (`night-sync.mjs`) и S37 (`build-album.mjs`) пишут в `data.album[]` (full+thumb в `static/uploads/album/`) — формат плоского списка менять нельзя, иначе ночная закачка сломается.

## Суть: вместо одного плоского списка — три управляемых объекта

1. **«Общий альбом "Коллектив"»** — именованный альбом-источник слайдера страницы «Коллектив» (`trainers.html`). **По умолчанию пуст** (ничего автоматически из «Совместные фото» не переносим; админ наполняет сам). Экспорт `trainer-slider.js` читает кадры из него; при пустом альбоме слайдер на странице не выводится (fallback на старый фильтр по категории — только если альбома в базе нет вовсе, чтобы поведение текущих сборок не изменилось незаметно).
2. **CRUD сущностей «альбомы»** (`albums[]`): `{ id, title, visible, order, photos: [{ image, thumb, caption }] }`.
   - у каждого альбома **свой заголовок** — выводится над его слайдером;
   - у каждого кадра **свой заголовок** (`caption`) — подпись кадра/слайда;
   - на странице «Альбом» каждый альбом = **отдельный слайдер** (не общая сетка);
   - **если есть хотя бы один** видимый непустой альбом — страница «Альбом» возвращается в навигацию (шапка/подвал), иначе ссылка скрыта;
   - выбор кадров — из банка `data.album[]` (поиск по категории/подписи) + загрузка нового файла; **дублей файлов в `uploads/` не создавать**, кадр хранит путь;
   - порядок альбомов и кадров — drag-and-drop (образец S100/S113);
   - API `get/save-albums` + санитизация (whitelist путей `uploads/`|`data/`, длина заголовков, удалённый кадр не должен оставлять битую ссылку); ключ `albums` добавить в `SETTINGS_KEYS` (`db-format.mjs`) — иначе потеряется при `nestDb` (тот же класс бага, что `halls`/`homeSections`);
   - экспорт: `album.js` дополнить срезом `albums` (или новый модуль `albums.js`), `album.html` переписать на слайдеры из него; текущая сетка `data.album[]` остаётся fallback, пока альбомов нет.
3. **«Не используемые фотографии»** — раздел-просмотр (только просмотр + массовое удаление файлов по галочкам с подтверждением): кадры из `data.album[]` и `static/uploads/`, не привязанные ни к чему — ни к программе/тренеру (`image`/`photoAlbum`), ни к новости (`image`/`video`/`photos`), ни к слайдеру, залам, ценам, логотипу, ни к одному из «альбомов» (п.2) и общему альбому (п.1). Показать: превью, путь, размер файла, категорию из `data.album[]`. Счётчик «N фото, M МБ».

## Шаги

1. Модель + `SETTINGS_KEYS`/миграция (пустые `albums`, пустой общий альбом «Коллектив»); ничего из `data.album[]` не удалять.
2. Сервер: `get/save-albums`, `get/save-collective-album` (или единый CRUD с флагом `kind: 'collective' | 'page'`), `get-unused-photos` (скан `uploads/` + сверка с использованием), удаление файлов — только внутри `static/uploads/` (защита от path traversal, как `handleDeleteNews`).
3. Экспорт: `albums`, кадры общего альбома → `trainer-slider.js`; `showOnHome`-подобный флаг страницы «Альбом» не нужен — ссылка появляется по факту непустых альбомов.
4. Админка: три подраздела в «📸 Альбом» (общий альбом / альбомы / неиспользуемые), редактор кадра с полем «подпись», выбор из банка, drag-and-drop, 👁🙈, «🔗 Открыть страницу альбомов».
5. `album.html`: секция-слайдер на альбом (заголовок альбома + заголовки кадров), lightbox, lazy-load; empty-state; `layout.js` (каркас S127) + `?v=`.
6. `header.js`/`footer.js`: ссылка «Альбом» — при наличии хотя бы одного видимого непустого альбома.
7. Тесты: round-trip CRUD альбомов (кадр с `caption` доезжает до сайта), пустой общий альбом → слайдера «Коллектив» нет, непустой → есть; «неиспользуемые» не считают занятым кадр, который стоит в альбоме; ни одного файла не удалено тестом без явной команды; `?v=` bumped.

## Критерий готовности

Админ собирает «Коллектив»-слайдер и произвольные альбомы без правки кода; страница «Альбом» показывает слайдеры с заголовками и появляется в меню только когда есть что показывать; неиспользуемые фото видны и чистятся; `data.album[]` и ночная закачка не сломаны.
