# S140 — Критический баг: удаление администратора затирает всю БД

**Приоритет:** критический  
**Статус:** активный  
**Найден:** 2026-11-09  

## Цель/постановка

При удалении администратора из `db.staff` через `/api/admin/save-staff` —
при повторном запуске админ-сервера все остальные данные исчезают.
БД содержит `{"data": {},"settings": {},"staff": []}`.

## Факты

- `handleSaveStaff` (строка 2809 admin-server.mjs) читает БД, изменяет `db.staff`,
  пишет обратно — сам по себе корректно.
- `handleSave` (строка 273) записывает `body.data` как ВСЮ базу без валидации
  содержимого: `flattenDb(body.data)` → если `body.data` пустой или неполный —
  данные теряются.
- Нет проверки, что перед записью база содержит обязательные ключи.
- Нет защиты от перезаписи непустой базы пустой/неполной.

## Шаги

1. Добавить валидацию в `handleSave`: проверять, что `body.data` содержит
   обязательные ключи (`data`, `settings`) и что `data.news`, `data.programs` и т.д.
   не пусты при перезаписи непустой базы.
2. Добавить в `handleSaveStaff` защиту: при пустом `sanitized` — предупреждение
   в лог и бэкап с меткой `before-staff-deletion`.
3. В `writeDb` добавить проверку минимальной структуры.
4. Настроить автоматический бэкап ПЕРЕД каждой операцией save (уже есть `backupDB()`
   в `handleSave`), но не в `handleSaveStaff` — там он тоже вызывается.
   Нужно проверить, что `backupDB()` вызывается до `writeDb()`, а не после.

## Критерий готовности

- Удаление последнего администратора не затирает остальные данные.
- Пустой/неполный `body.data` в `/api/admin/save` отклоняется с ошибкой.
- Тест: `scripts/test-static.mjs` покрывает сценарий "save empty → 400".
