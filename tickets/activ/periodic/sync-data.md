# 🔄 periodic/sync-data — Подгрузка данных с сайта (прод) и из CRM

> **Периодичность:** перед каждой деплой-пачкой (данные прода могут измениться),
> по запросу пользователя, при рассинхроне дев ↔ прод.

## Источники данных

| Источник | Что тянем | Инструмент |
|----------|-----------|-----------|
| Прод `https://центр-фр.рф` | Новости с картинками (главная ценность на проде) | `npm run pull-prod-news` (`scripts/pull-prod-news.mjs`, идемпотентно, `--dry-run`, откат на снимок при недоступности прода) |
| Яндекс.Диск | Фото/описания тренеров и программ | `python3 scripts/yandex-download.py` (resume), `npm run parse-docs`, `npm run night-sync` (или cron `# CFR-NIGHT` на сервере) |
| CRM (DanceStudio) | Данные личного кабинета | `static/lk.html` — страница работает напрямую с Dropbox API (клиентское приложение); отдельной загрузки нет. ⚠️ base64-учётные данные Dropbox внутри страницы — известный риск, менять только отдельным тикетом |
| Прайс-документ | Цены и скидки | `npm run parse-price` (идемпотентно: обновляет цены, не трогает правки админки) |

## Чек-лист

- [ ] `npm run pull-prod-news -- --dry-run` — сверить новости прода и девела
- [ ] При расхождении — стянуть (новости прода **старше/новее** девельских — сверять даты)
- [ ] `npm run night-sync` (или дождаться cron на сервере) — докачка фото, парсинг docx
- [ ] `npm run parse-price` — цены актуальны (dry-run → `--write` при необходимости)
- [ ] `npm run static:export` — экспорт после любой правки `db.json`
- [ ] Бэкап `db.json` перед каждой массовой правкой (правило проекта)

## Важные факты

1. Сайт читает данные **НЕ** из `db.json`, а из `static/js/data/*.js` —
   после любой правки базы обязателен `npm run static:export`.
2. `db.json` — вложенный (`data.*`, `settings.*`); скрипты работают с плоским через
   `flattenDb`/`nestDb` (`scripts/db-format.mjs`).
3. Прод хранит пути к файлам без ведущего слэша, дев — с ведущим; в базе нужна конвенция девела.
4. Имена/байты картинок новостей оставлять как на проде → деплой не затрёт прод-версию.
