# 🔄 periodic/trash-cleanup — Уборка: неактуальные документы и код в trash

> **Периодичность:** по мере накопления; после закрытия крупных волн; по команде
> «приберись в задачах» (см. `tickets/README.md`).

## Правила уборки (из AGENTS.md — критично)

1. **Никогда не удалять файлы напрямую** — только **перемещение** в `trash/` (gitignore,
   прецедент: S65 перенёс старый Next.js в `trash/`).
2. Удаление возможно **только** после ознакомления пользователя со списком
   и только через корзину.
3. Ничего не менять за пределами проекта.

## Чек-лист

### Документы

- [ ] Просроченные/закрытые тикеты → перенести в `tickets/done/*.md` (правило тикет-системы)
- [ ] Старые мультитикеты, полностью выполненные → в `trash/` (после подтверждения пользователя)
- [ ] tickets/ — закрыть выполненные тикеты (в done/)
      (прецедент сессии 36: перенос дословно, по границам заголовков, с бэкапом)
- [ ] Временные отчёты/анализы (project-analysis, аудиты) — проверить актуальность,
      неактуальные → `trash/` (с подтверждения)

### Код и данные

- [ ] Мёртвые скрипты в `scripts/` (не вызываются из package.json и cron) → `trash/scripts/`
- [ ] Артефакты сборки/кэши (`node_modules/.cache`, `.next`) — можно чистить напрямую
- [ ] `static/data/` — исходники Яндекс.Диска (гигабайты, в git не входят) — не трогать без команды
- [ ] Неиспользуемые фото в `static/uploads/` — кандидаты: раздел «Не используемые
      фотографии» из S136 (`tickets/definded/S136-admin-album.md`)
- [ ] `db.json.backup.*`, `backups/` — оставить последние N (3–5), старые → `trash/`

### Git

- [ ] `git status` чистый или объяснимый; временные файлы в `.gitignore`
- [ ] Коммиты/пуш — только по команде пользователя
