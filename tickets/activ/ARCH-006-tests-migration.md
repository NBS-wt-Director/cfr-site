# ARCH-006 — Перенос тестов: test-static.mjs → тесты шаблонов + API на pg-фикстурах

> **Статус:** 📋 Запланирован (2026-11-14). Блокируется ARCH-004.
> Поставлен 2026-11-14.

## Постановка

Текущий `scripts/test-static.mjs` (~875 проверок) проверяет **файлы статики**:
`static/js/data/*.js`, HTML-файлы с `?v=`, CSS, экспортированные структуры.
После ARCH-004 файлов-источников нет → тесты переносятся на:
1. **HTML шаблонов** (рендер через SSR-функцию с фикстурами),
2. **API админки** (supertest по compose-контуру с pg),
3. **Бизнес-логику** (санитайзеры, резолвер S18, валидаторы — юнит-тесты).

## ФАКТЫ

- ~875 проверок, группировка по тикетам (S11…S170) — группировку сохраняем (трассировка фич).
- jsdom уже используется (рендер-проверки) — переносится в новый стек почти как есть.
- Часть проверок — «структура js/data» (формат экспорта) → **упраздняются вместе с экспортом**
  (фиксируются списком в журнале, не молча).
- 2 преждественных падения (S32 чипы, S28 обложки) — при переносе перепроверить и закрыть или
  перенести как живые.

## ШАГИ

1. Инвентаризация: прогнать текущий набор, разметить каждую проверку —
   `→ шаблон` / `→ API` / `→ юнит` / `→ упразднён (нет статики)`. Таблица — в `documentation/TESTS-MAP.md`.
2. Стек: **Vitest** (+ jsdom environment) + **supertest**; контейнер-контур
   `compose.test.yml` (pg с фикстурами, app).
3. Миграция по группам тикетов (порядок: критичные — S155 письма, S140 валидация, S18 резолвер,
   S151/S166 лиды/events → затем UI-шаблоны → затем косметика).
4. Фикстура-база: снимок прод-данных (ARCH-002 импорт) — детерминированный pg-дамп `tests/fixtures/`.
5. Порог входа в CI: все перенесённые зелёные; упразднённые — списком в отчёте.
