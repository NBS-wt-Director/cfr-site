## ФАКТЫ

### Два разных пути отправки

| Путь | Работает? | Код |
|---|---|---|
| Тестовое письмо из админки | ✅ ДА | `handleSendTestEmail` — читает `readDb()`, `nodemailer`, синхронно ждёт `await sendMail`, ошибку возвращает в UI |
| Письмо о новой заявке | ❌ НЕТ | `sendLeadNotification` — вызывается из `handleCreateLead` как `sendLeadNotification(lead).catch(() => {})` — **ошибка глотается полностью** |

### Корневые причины (решены в этом тикете)

1. **Код S153 не был задеплоен на прод.** `sendLeadNotification` появился в коммите `e55d100` (2026-11-10).
2. **`smtpPass` мог затереться при деплое.** Мержер до этой правки защищал только пустые строки.
3. **Ошибка SMTP не видна.** `.catch(() => {})` + `console.warn` → в логах PM2 теряется.
4. **Письмо не проходило фильтр Яндекса.** Тема не начиналась с «Заявка:», From содержал display name.

## ШАГИ (выполнены 2026-11-10)

### ✅ S155.1 — `logs/leads-email.log` (журнал ошибок SMTP)

- Функция `logLeadEmail()` пишет timestamp, to, messageId, ошибку в `logs/leads-email.log`.
- `sendLeadNotification` вызывает `logLeadEmail` при успехе, пустом пароле, и ошибке.

### ✅ S155.2 — Защита `smtpPass` при деплое

- `deploy-merge-db.mjs`: `SECRET_KEY_RE = /pass|secret|token|password/i`
- Если серверный ключ совпадает с паттерном и непустой — **серверный всегда побеждает**.
- Проверено функционально: серверный `НОВЫЙ_ПАРОЛЬ` сохранён, репозиторный `СТАРЫЙ_ПАРОЛЬ_ИЗ_РЕПО` не затёрт.

### ✅ S155.3 — Шаблон письма (старый концепт Next.js send-email/route.ts)

**Отправитель:** `from: '"<smtpUser>" <smtpUser>'` — ровно как в старом шаблоне, проходит фильтр Яндекса «От кого содержит «"centr-fr@yandex.ru" <centr-fr@yandex.ru>»»
**Тема:** `🐼 Заявка: {name} ({page})` — содержит «Заявка:» (фильтр Яндекса: «Тема содержит Заявка: → папка Заявки с сайта»)
**HTML:** зелёный блок с эмодзи, поля Имя/Телефон/Email/Желание/Сообщение, «⚡ Срочно перезвоните клиенту!»
**Текстовая версия:** совпадает с HTML для клиентов без HTML-почты.
**Убрано из письма:** UA (есть в leads.json), ISO-время → `formatLeadTime()` → человекочитаемое «10.11.2026 14:12 (Екб)»

### ✅ S155.4 — emailSent в UI админки

- `markLeadEmailSent(leadId, true/false, error)` обновляет `emailSent` и `emailError` в leads.json.
- Колонка «✉️ Письмо» в таблице заявок: ✅ отправлено / ❌ не отправлено (с подсказкой ошибки).
- Старые заявки без emailSent показывают «—» (сервер до S155).

  - «Есть вопрос…» ТОЛЬКО для шапки/подвала/плавающей.
