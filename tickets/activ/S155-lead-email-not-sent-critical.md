# S155 — КРИТИЧНО: письмо из формы не уходит (тестовое из админки уходит)

> **Статус:** 🔴 Активен, приоритет №1 (поставлен 2026-11-10, пользовательский запрос)

## Постановка (слова пользователя)

> «отправка писем так и не починилась... при чём тестовое письмо из админки идёт.
> а вот письмо из формы — нет. это первоочередное.»
> «на всякий был обновлён пароль почты — <ADMIN_PROVIDED_APP_PASSWORD>. он должен попасть на сайт»

## ФАКТЫ

### Два разных пути отправки
| Путь | Работает? | Код |
|---|---|---|
| Тестовое письмо из админки | ✅ ДА | `handleSendTestEmail` — читает `readDb()`, `nodemailer`, синхронно ждёт `await sendMail`, ошибку возвращает в UI |
| Письмо о новой заявке | ❌ НЕТ | `sendLeadNotification` — вызывается из `handleCreateLead` как `sendLeadNotification(lead).catch(() => {})` — **ошибка глотается полностью** |

### Корневые причины (проверяются по этой же очерёдности)

1. **Код S153 ещё не задеплоен на прод.**
   `sendLeadNotification` появился в коммите `e55d100` (2026-11-10). Если прод не обновлялся —
   маршрут `lead-create` просто не отправляет письма. Тестовое письмо при этом работает,
   т.к. `handleSendTestEmail` старый и уже на проде. **Это самая вероятная причина.**

2. **`smtpPass` пустой в серверном `db.json`.**
   Локально в репо: `"smtpPass": ""`. Проверка `if (!smtpUser || !smtpPass) return;`
   молча пропускает отправку. Тестовое письмо на проде работает ⇒ на проде пароль есть
   (введён админом в UI). Но при деплое `deploy-merge-db.mjs` может не перенести
   серверный `smtpPass` в объединённую базу — **проверить стратегию мержа emailConfig!**

3. **Ошибка SMTP не видна.** `.catch(() => {})` + `console.warn` → в логах PM2 теряется.
   Нужен журнал: `logs/leads-email.log` с текстом ошибки.

4. **Письмо уходит с `from = smtpUser` на `to = adminEmail`, где `adminEmail === smtpUser`**
   (оба `centr-fr@yandex.ru`). Яндекс такую «самому себе» переписку может относить в «Спам»
   или подавлять. Тестовое письмо при этом уходит, т.к. туда же — значит не блокируется,
   но **проверить папку «Спам»** на centr-fr@yandex.ru.

### Что нужно сделать

1. **Пароль приложения** — записать `<ADMIN_PROVIDED_APP_PASSWORD>` в `db.json → emailConfig.smtpPass`
   (секрет в коммитить нельзя по AGENTS.md §2 — но исторически `smtpPass` уже живёт в db.json;
   решение пользователя: «он должен попасть на сайт». На проде пароль вводится через
   админку → «Настройки почты», и деплой-мерж обязан его сохранять.)
2. **`sendLeadNotification`** — писать результат/ошибку в `logs/leads-email.log` (timestamp, to, ошибка).
3. **`deploy-merge-db.mjs`** — проверить, что серверный `emailConfig.smtpPass` не теряется при мерже
   (сервер — источник истины для пароля).
4. **Диагностика в UI**: в разделе заявок показывать, отправлено ли письмо (поле `emailSent` в lead).
5. Проверить на проде: `pm2 logs cfrsite` — строки `📧 Уведомление` / `⚠️ Не удалось`.

## Критерий готовности
- Новая заявка с сайта → письмо на `centr-fr@yandex.ru` приходит (не в спам)
- При сбое SMTP в `logs/leads-email.log` видна причина
- После деплоя серверный `smtpPass` сохранён
