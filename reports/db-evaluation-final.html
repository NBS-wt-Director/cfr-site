✅ СИЛЬНЫЕ СТОРОНЫ

  • Persons-центричность: все данные о человеке в одном месте, роли через FK 1:1
  • 24 ENUM-типа: type-safe, нет опечаток, быстрый индекс
  • 49 таблиц: плоские, нормализованные до 3NF
  • XSS-защита на уровне БД: 5 триггеров BEFORE INSERT/UPDATE
  • Мост данных: триггеры автопереноса + ручная обработка
  • legacy_data TEXT: уникальные данные сохранены, не потеряны
  • Документация: COMMENT ON для 15 таблиц + 12 колонок
  • JSONB запрещён: только bridge_queue, как требовалось

⚠️ ЧТО ОСТАЛОСЬ ДЛЯ CRM (legacy_data)

legacy_data — это архив, не структура:
  • cfr_accounts.legacy_data → Groups, Reservations, Stages, Visits, BurnRes, Bonus, Schedule, TenantType
  • cfr_clients.legacy_data → CardUses, Deposit, Bonus, Comments, Tasks, StatusChanges, Files
  • cfr_visits.legacy_data → Visits, Bonus, Deposit
ПРАВИЛА:
  • НЕ ПАРСИТЬ при миграции — бережно переносим сериализованную строку как есть
  • НЕ ПОКАЗЫВАТЬ в ЛК — первая версия работает без этих данных
  • ДЛЯ CRM ПОЗЖЕ — разберёмся после первой версии ЛК
  • TEXT (НЕ JSONB!) — JSONB запрещён везде, кроме bridge_queue
