## 3. ФОРМАТЫ DOCX (что парсить)

Всего на дисках: **32 docx программ** (в т.ч. в архивах) и **15 docx тренеров**.

### 3.1. Программы — Формат A («inline», без `====`) — ОСНОВНОЙ

```
<Название>
<Строка(и) расписания: дни + время>
<абзацы описания>
Тренер | Тренера | Педагог
<ФИО тренеров, по одному в строке>
```

- Расписание — сразу под названием; может быть **несколько строк**
  (пример «Здоровая спина», «Тайцзи-Цюань»).
- Разделители дня и времени: и `::` (`Суббота :: 17:00-17:50`), и просто
  пробелы (`Понедельник 20:00-20:55`), и `,` (`Среда 20:00-20:55, Суббота 18:00-18:55`).
- Дни могут быть **со строчной буквы** (`вторник :: 18:00-18:50`).
- Маркер секции тренеров: `Тренер`, `Тренера`, `Педагог`, иногда **слитно** с ФИО
  (`ТренерКузнецов Александр Вячеславович`).
- Список тренеров может быть через запятую и/или переносы.

### 3.2. Программы — Формат B («секции через `====`»)

```
<Название>
====
<Описание>
====
<ФИО тренеров через запятую>
====
<Расписание>
====
<Имя файла обложки>
====
<Фото: "файл :: подпись; файл :: подпись; …">
```

- Число секций варьируется: часть секций может отсутствовать/быть пустой
  (напр. `ОФП Ушу (10+)` — секция фото пустая).
- В секции фото встречаются «мусорные» подписи (`о;`, пустые) — фильтруются.

### 3.3. Тренеры — Формат T1 (`Описание.docx`, «новый»)

```
ФИО: <ФИО>
Стаж Ушу: <…>
Тренерский стаж: <…>
Специализация: <…>
Образование:
<…>
Девиз: "<…>"
```

- Маркеры **могут слипаться** с предыдущим значением без переноса
  (`…(16 лет)Специализация: «…»`) — нужна вставка переноса перед маркером.
- Встречается `Стаж УШУ:` / `Стаж ушу:` (регистр).

### 3.4. Тренеры — Формат T2 (именной docx, «старый»)

```
<ФИО>            (иногда с артефактным числом перед ним: 176974551625500Кравец…)
<строка-подпись>
Тренерский стаж: <…>
Специализация: <…>
Образование:
<…>
Девиз: / Девиз Елены:
```

- В папках, где есть **оба** файла (`Описание.docx` + `Кравец Оксана.docx` и т.п.),
  парсер должен **объединять** оба (generic + named) — текущая логика сохранена.
- Именные docx есть у: `Кравец Оксана`, `Кузнецов Александр`, `Половникова Тамара`,
  `Хорошилова Елена`, `Поторочин Станислав`.

### 4.1. Про «с сервера и из админки»

- **Из админки:** кнопки `🔄 Обновить данные с диска` (`/api/admin/sync-data` →
  `night-sync.mjs`) и `📄 Парсить DOCX` (`/api/admin/parse-docs` → `parse-docs.mjs`)
  уже есть в `static/admin.html` и `scripts/admin-server.mjs`. Ломается сам
  пайплайн из-за п.1–8 выше.
- **С сервера:** `npm run night-sync` (крон) вызывает `yandex-download.py` →
  `parse-docs.mjs` → `static:export`. `yandex-download.py` качает **только фото**
  (`.mov/.mp4` пропускает) и **рекурсивно** — служебные/архивные папки тоже
  скачает (это ок для фото, но требует фильтрации на этапе парсинга).
